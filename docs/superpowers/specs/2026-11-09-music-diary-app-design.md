# 음악 기록 & 친구 공유 iOS 앱 — 설계 문서

작성일: 2026-11-09
상태: 승인됨 (빌더 검토 반영, 2026-11-09)

> 표기: **[결정]** 사용자가 직접 정한 것 · **[제안]** 대화 중 Claude가 제안하고 사용자가 이의 없이 넘어간 것 · **[빌더 재량]** 구현자가 정해도 되는 것

---

## 1. 의도와 이유

"언제, 어디서, 어떤 마음으로 이 노래를 들었는지"를 짧게 남기는 음악 일기 앱이다. 두 가지를 이루려고 한다. **[결정]**

1. **나만의 음악 아카이브**: 기록이 쌓이면 날짜와 장소로 다시 꺼내 볼 수 있다.
2. **친구와 노래가 연결되는 모습을 눈으로 보기**: 한 곡이 친구들 사이로 어떻게 퍼졌는지를 별자리 그림으로 보여준다. 이것이 이 앱을 다른 음악 SNS와 구별하는 핵심이다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 세로 스와이프 피드로 친구와 모두의 기록을 구경하면서 노래 미리듣기를 들을 수 있다.
- 기록 하나를 30초 안에 남길 수 있다.
- 친구 카드에서 탭 한 번으로 그 노래를 내 아카이브에 저장하고, 그 연결이 별자리로 남는다.
- 아카이브를 날짜와 장소로 정리해 볼 수 있다.

**비목표 (이번 버전에서 하지 않음)**
- 감정 태그나 감정별 정렬. 사용자가 명시적으로 뺐다. **[결정]**
- 전곡 재생. 미리듣기(30초)까지만 한다.
- 안드로이드나 웹.
- 추천 알고리즘. 전체 탭은 최신순이다. **[제안]**

**반목표 (기술적으로 동작해도 실패인 것)**
- "나만 보기" 기록의 내용(코멘트, 장소, 시간)이 다른 사람에게 노출되는 것.
- 친구 카드에서 저장한 것이 내 피드 글로 올라가는 것. 저장은 아카이브 전용이다.
- 별자리가 비어 보이는 것. 저장만 해도 별이 뜨게 한 이유가 이것이다.

## 3. 제약

- **iOS 네이티브 (SwiftUI)**: 사용자가 iOS 앱을 원했다. **[결정]**
- **Apple MusicKit**: 곡 검색, 메타데이터, 앨범 아트, 30초 미리듣기에 쓴다. 사용자는 Apple 개발자 계정을 이미 갖고 있다. **[결정]**
- **백엔드는 Supabase** (Postgres, Auth, Row Level Security). **[결정]**
- **App Store 심사 요건**: 사용자가 만든 콘텐츠를 다루는 앱(가이드라인 1.2)이므로 다음이 필요하다.
  - 신고 기능
  - 사용자 차단 기능
  - 부적절한 콘텐츠에 대응할 방법
  - 앱 안에서 계정을 삭제하는 기능 (5.1.1(v))

  "전체" 탭이 있으므로 이 기능들은 빠질 수 없다.
- **로그인은 Sign in with Apple 하나만** 둔다. **[제안]**

## 4. 접근 방식 (검토한 대안)

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. Supabase (채택)** | Postgres + RLS + Auth | 친구 관계와 "누가 누구에게서" 관계를 테이블 관계로 그대로 표현할 수 있다. 별자리 데이터는 재귀 쿼리 한 번으로 꺼낸다. 공개 범위를 DB 레벨(RLS)에서 강제하므로 앱 버그가 있어도 비공개 내용이 새지 않는다. | 스키마를 처음에 신중히 설계해야 한다. |
| B. Firebase | Firestore 문서 DB | 시작이 빠르고 실시간 기능이 쉽다. | 친구 피드와 별자리 탐색에 비정규화와 fan-out이 필요하다. 보안 규칙이 복잡하고, 비용이 읽기 횟수에 비례한다. |
| C. CloudKit | Apple 자체 저장소 | 서버 비용이 거의 없다. | 전체 공개 탭과 친구 공유 모델을 만들기 어렵다. 다른 플랫폼으로 확장할 수 없다. |

자체 서버를 두는 안은 운영 부담 때문에 처음부터 제외했다. 사용자가 A를 선택했다. 이유는 공개 범위와 별자리 연결이 관계형 구조와 가장 잘 맞기 때문이다.

## 5. 결정된 화면과 동작

### 5.1 하단 메뉴 **[제안]**
`피드` · `＋기록` · `아카이브` (프로필과 친구 관리는 아카이브 화면 상단에서 들어간다 **[빌더 재량]**)

### 5.2 피드 **[결정]**
- 세로 스와이프 풀스크린 카드 (릴스, 쇼츠 형태).
- 상단에서 **[친구 | 전체]** 탭을 전환한다 (BeReal식).
  - **친구 탭**: 나와 친구들이 "친구에게" 또는 "전체에게"로 올린 기록. 내 기록과 친구 기록이 섞여서 시간순으로 이어진다.
  - **전체 탭**: 앱 사용자 모두의 "전체에게" 기록. 최신순이다. **[제안]**
- 카드 구성: 앨범 아트, 곡명과 아티스트, 30초 미리듣기 자동 재생, 들은 시간, 장소, 코멘트, 작성자. 다른 사람에게서 온 기록이면 "🔗 OO에게서 온 노래"를 표시한다.
- 카드에서 할 수 있는 것:
  - **저장**: 내 아카이브에 저장 (5.4)
  - **별자리 보기**: 이 곡의 별자리 화면 (5.5)
  - **신고/차단**: 남의 카드일 때
- "아카이브에 저장"으로만 남긴 항목은 어떤 피드에도 나오지 않는다. **[결정]**

### 5.3 기록하기 **[결정]**
입력 항목은 다음과 같다.
1. **곡**: MusicKit 카탈로그 검색으로 고른다.
2. **언제**: 기본값은 지금이고 수정할 수 있다.
3. **어디서**: 현재 위치 근처 장소 목록(MapKit POI)에서 고르거나 직접 입력한다. 생략할 수 있다. **[제안]** 근처 장소를 고르면 이름과 좌표를 저장하고, 직접 입력하면 이름만 저장한다.
4. **코멘트**: 자유 텍스트. **감정 선택 UI는 없다.** **[결정]**
5. **공개 범위**: `나만 보기` / `친구에게` / `전체에게`. **[제안]** 기본값은 빌더 재량이지만 `친구에게`를 권장한다.

### 5.4 친구 카드에서 저장하기 **[결정]**
- 남의 카드에서 "저장"을 누르면 그 곡이 **내 아카이브에만** 들어간다. 피드에는 올라가지 않는다.
- 저장 시각은 자동으로 기록된다. 장소는 위치 권한이 있으면 근처 장소를 자동으로 제안하고, 없으면 비워 둔다. 코멘트는 나중에 아카이브에서 추가할 수 있다. **[제안]**
- 저장 항목은 **어느 카드에서 왔는지**(출처 기록)를 기억한다. 이것이 별자리의 선이 된다.

### 5.5 별자리 (곡별 연결 화면) **[결정: 별자리 모양]**
- 어두운 배경 위에 **사람은 별(점), 노래가 건너간 길은 선**으로 그린다.
- **점 색 = 친구마다 고유한 색.** 감정 색이 아니다. 같은 색을 프로필과 피드에서도 쓴다. **[제안]**
- **점 크기 = 그 사람을 거쳐 퍼진 수.**
- 연결은 두 종류다.
  - **퍼진 흐름 (C)**: 저장 항목의 출처 기록을 따라 선을 긋는다. 주된 연결이다.
  - **같은 노래 (A)**: 출처 없이 같은 곡을 따로 기록한 친구도 별로 표시한다. 선은 없거나 옅게 그린다. **[제안]** 초반에 별자리가 비어 보이지 않게 하는 용도다.
- **저장만 한 사람도 별로 뜬다.** 단, 그 저장 항목의 코멘트, 장소, 시간은 보이지 않는다. **[결정]**
- 별을 누르면 그 사람이 이 곡에 남긴 기록 카드가 뜬다. 볼 권한이 없는 내용은 "저장함"으로만 표시한다. **[제안]**

### 5.6 아카이브 **[결정: 날짜·장소 두 가지]**
- 상단 세그먼트: `[날짜 | 장소]`. 감정 정렬은 없다.
- **날짜**: 월 달력. 기록이 있는 날 칸에 앨범 아트를 표시한다. 하루에 여러 곡이면 대표 하나와 개수를 표시한다 **[빌더 재량]**. 날짜를 누르면 그날 기록 목록이 나온다.
- **장소**: 위쪽은 지도(장소별 곡 수 표시), 아래쪽은 "자주 들은 곳" 목록. 장소를 누르면 거기서 들은 곡 목록이 나온다. 좌표가 없는 직접 입력 장소는 목록에만 나오고, 이름이 같을 때만 묶인다. **[제안]**
- 아카이브에는 내가 올린 기록과 저장한 항목이 모두 나온다. 저장 항목은 출처("민지에게서")를 표시한다.

### 5.7 친구 **[제안]**
- 아이디(핸들) 검색 또는 초대 링크로 친구 요청을 보낸다. 상대가 수락하면 상호 친구가 된다.
- 차단하면 친구 관계가 끊기고, 서로의 기록이 피드와 별자리에서 사라진다.

## 6. 데이터 모델 스케치 (빌더가 다듬을 것)

```
profiles      (id = auth.uid, handle unique, display_name, star_color, created_at)
friendships   (user_a, user_b, status: pending|accepted, requested_by, created_at)
blocks        (blocker, blocked)
songs         (apple_music_id PK, title, artist, artwork_url, cached_at)
entries       (id, user_id, song_id, listened_at, place_name?, place_lat?, place_lng?,
               comment?, visibility: private|friends|public,
               kind: post|save,
               source_entry_id? → entries.id,   -- 어느 카드에서 왔나
               created_at)
reports       (reporter, entry_id, reason, created_at)
```

- **피드에 나오는 것**: `kind = post` 이고 `visibility != private`.
- **별자리 데이터**: 같은 `song_id`의 entries 중 조회자에게 "존재"가 보이는 것 + `source_entry_id` 간선.
- **RLS 원칙**: entry 존재(작성자, 곡, 출처)를 볼 수 있는 범위와 entry 내용(코멘트, 장소, 시간)을 볼 수 있는 범위를 분리한다. 저장 항목은 존재만 공개하고, 내용은 공개 범위를 따른다. 뷰 또는 보안 함수로 구현한다. **[빌더 재량: 방식]**
- **미리듣기**: MusicKit의 `previewAssets` URL을 AVPlayer로 재생한다. 미리듣기 URL을 DB에 영구 저장하지 말고 런타임에 조회한다. **[빌더 재량]**

## 6.4 빌더 검토 후 사용자가 정한 것 **[결정]**

- **다단계 확산**:
  - 아카이브에 저장한 항목에 **"피드에 올리기"** 버튼이 있다.
  - 올리면 해당 항목이 `kind = post`가 된다. 이때 공개 범위를 고르고, 코멘트와 장소를 덧붙일 수 있다.
  - `source_entry_id`는 그대로 유지되며, 피드 카드에 "🔗 OO에게서 온 노래"로 표시된다.
  - 다른 사람은 이 글에서 다시 저장할 수 있다. 그래서 A → B → C 체인이 생기고, 별자리 쿼리는 재귀로 체인을 따라간다.
- **별자리 범위**:
  - 체인을 끝까지 따라가되, **친구는 이름과 고유 색으로, 친구가 아닌 사람은 이름 없는 회색 별로** 표시한다. 회색 별은 탭해도 내용이 보이지 않는다.
  - 크기(퍼진 수)는 회색 별까지 포함해 계산한다.
- **신고 처리**:
  - 운영자(사용자 본인)가 직접 처리한다.
  - 같은 기록에 신고가 3회 누적되면 자동으로 숨긴다(`hidden` 상태). 숨김은 RLS에서 반영한다.
  - 신고가 들어올 때마다 운영자에게 이메일 알림을 보낸다(Supabase Edge Function 또는 DB webhook).
  - 검토와 삭제는 Supabase 대시보드에서 한다. 별도 관리자 앱은 만들지 않는다.

## 6.5 빌더 검토 후 Claude가 정한 것 **[제안 · 사용자 승인]**

- **저장 항목의 공개 범위**: 저장 항목의 내용(나중에 덧붙인 코멘트, 장소)은 항상 `나만 보기`다. 별자리에는 "존재"만 나온다. 아카이브 편집 화면에는 공개 범위 선택 UI가 없다.
- **"나만 보기"로 올린 일반 기록**: 출처 연결이 없으면 별자리에 별로 뜨지 않는다. 독립적으로 들은 비공개 기록까지 노출하면 "나만 보기"의 의미가 약해지기 때문이다.
- **중간 기록이 사라질 때** (삭제, 비공개 전환, 계정 삭제):
  - 아래쪽 저장과 기록은 남긴다.
  - 끊긴 자리에는 이름 없는 회색 별("사라진 별")을 둔다.
  - `source_entry_id`는 그대로 두고, 원본 행은 내용을 지운 tombstone으로 남긴다.
  - 계정 삭제 시 개인 데이터(프로필, 코멘트, 장소)는 하드 삭제하고, 연결 구조만 익명으로 남긴다.
- **차단된 사람이 체인 중간에 있을 때**:
  - 경로는 유지한다.
  - 차단된 사람은 이름 없는 회색 별로 보인다.
  - "OO에게서" 라벨은 "누군가에게서"로 바꾼다.
  - 필터링은 클라이언트가 아니라 쿼리와 RLS 레벨에서 한다.
- **같은 노래 판정**:
  - ISRC가 같으면 같은 곡으로 본다 (싱글, 앨범, 리마스터 통합). ISRC가 없으면 카탈로그 ID로 판정한다.
  - `songs` 테이블은 ISRC 기준 그룹 키를 가진다.
  - 스토어프론트는 사용자 기기의 것을 쓰고, 기본 대상 시장은 한국이다.

## 7. 빌더에게 맡기는 것

- SwiftUI 내부 구조(아키텍처 패턴), 패키지 선택, 이미지 캐싱
- 피드 페이지네이션과 미리듣기 프리로드 전략
- 별자리 레이아웃 알고리즘 (force-directed 등)과 애니메이션
- 시각 디자인 세부: 어두운 톤 기조만 결정됨
- 테스트 전략
- Supabase 마이그레이션 관리 방식
